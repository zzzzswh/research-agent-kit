# research-agent-kit v2：提纲驱动的 AI 协作开发

## 一句话

**平时：人列提纲，AI 在提纲里插值；需要外推的地方，AI 标出来交给人定。**
**自动驾驶：AI 自己开车（允许外推），但在和人工文档隔离的地方，随时把路线图摊开。**

文档有两个作用：让人随时看懂 AI 在干什么、打算干什么；同时它也是人给 AI 的指令。代码必须和文档一致。

## 为什么是"插值 / 外推"

- 人列出标题和要求，就是给了锚点。AI 在锚点之间填内容：补全人的意思、写清代码在哪里、把跑出来的结果写回文档。这是插值，可靠。
- AI 自己想方案、下判断、引用没核实过的东西，就是外推。幻觉、bug、理解偏差，大多来自这里。
- 所以 AI 写进文档的每一句话，只能是三类之一：复述、有出处的事实、标了【待确认】的提案（见 `AGENTS.md` 铁律二）。
- AI 做不好，人也有一半责任，多半是提纲没把事情和方法说清楚。出了问题要先分清是"提纲没说清"还是"执行错"，两者的改法不一样（`AGENTS.md` 第 7 节）。

## 三道闸

| 风险 | 闸 |
|---|---|
| 幻觉 | 铁律二：无出处的事实不写；没核实过的旧文档不引用 |
| 理解错 | 先改文档再改代码：文档的改动就是 AI 把"我理解要做什么"写给人看 |
| bug | 测试，加上人在真实环境里跑出的输出和验收图；没有证据不能删【待实现】 |

## 两种模式

| | 平时（插值） | 自动驾驶（允许外推） |
|---|---|---|
| 谁定方法 | 人列提纲，AI 填 | AI 自己探索、试验、纠错 |
| 碰到需要外推 | 停下来问人 | 不停，自己做，但在行车记录里留痕 |
| AI 写哪里 | 人写的文档（按铁律二） | 只写隔离区 `docs/auto/<日期>-<名>/` |
| 人怎么跟上 | 看文档改动 | 看路线图 `ROUTE.md`：现在怎么做、打算怎么做、离目的地多远 |
| 人管什么 | 提纲 | 目的地、验收标准、预算、禁区 |
| 结束后 | — | 人审提案和代码，决定合并什么、搬什么进正式文档，也可以整段丢弃 |

自动驾驶是终极目标：车由 AI 开，但路线图要一直摊开给人看。为了能分清哪些判断可以信，自动驾驶文档里每个判断都标【事实】【推断】或【猜测】；每一轮的假设和判据必须在跑之前写下，防止事后凑结论。详见 `.agents/skills/auto-drive/SKILL.md`。

## 人这边：怎么把事情和方法说清楚

每个小节的要求写清四件事：

1. **做什么**：目标。
2. **用什么方法**：已经想好的就直接写；还没想好的，写"调研：……"，让 AI 出候选方案。
3. **怎么算做完**：跑什么测试、看什么图、数字到多少。
4. **参照与约束**：对标什么、不能碰什么。

例子：

| 说得不够清楚 | 说清楚了 |
|---|---|
| 把噪声强度做均匀 | 噪声强度在 C_cf ∈ [2, 17.5] dB 上均匀，另有 1/12 的道集完全不加噪；按任务分层抽样。验收：均匀度（最大箱 / 最小箱）≤ 1.5，偏离目标超过 1 dB 的道集 < 3% |
| 加点噪声 | 陆上五种噪声：白噪声、正弦、斑点、局部条带、工业电（OBN 不加工业电）；概率和幅度沿用之前的取值 |
| 研究一下预处理 | 调研：统一预处理有哪些候选。要求同时保留初至前后的强弱对比和波形形态；评判时不看测试集；给出推荐 |

## 文件

| 文件 | 作用 |
|---|---|
| `AGENTS.md` | 通用约定：两条铁律、两个标记、停车条件、流程、出错归因、回复格式、红线 |
| `CLAUDE.md` | 给 Claude Code，一行引入 `AGENTS.md` |
| `docs/SPEC.md` | 项目规格模板：目标、各部分要求、本项目约定、执行顺序表。由人填写 |
| `docs/TOPIC_TEMPLATE.md` | 主题文档模板：人写标题和要求，AI 填做法、出处、结果；末尾是更正附录 |
| `.agents/skills/auto-drive/SKILL.md` | 自动驾驶：人给目的地、预算、禁区；AI 在隔离区维护路线图、行车记录、提案；自我纠错；什么时候停；收车交付 |

## 安装

1. 把 `AGENTS.md`、`CLAUDE.md`、`.agents/` 放进仓库根目录，把 `docs/SPEC.md` 放进 `docs/`，然后填写。
2. Codex 直接读 `AGENTS.md`；Claude Code 读 `CLAUDE.md`，它会引入 `AGENTS.md`；其他工具在各自的规则文件里写一句"先读 AGENTS.md"。
3. 如果工具只认自己的技能目录，就建一个软链指向 `.agents/skills`。

## 从 v1 升级

v1 的 `PROJECT.md`、`TODO.md`、`docs/modules/` 四段式，以及 research-flywheel、log-finding、release-component、data-inspect 几个技能都去掉了：

- 故事线 → SPEC 的项目目标；
- TODO → SPEC 的执行顺序表；
- "错误的认识与原因" → 历史交给 git，需要留痕的写进主题文档末尾的更正附录；
- 飞轮、落盘、发版 → `AGENTS.md` 第 6 节流程和第 11 节提交；
- 数据检查的出图约定 → 各项目 SPEC 的"本项目约定"。

v1 的 paper-writing 技能和这套约定无关，需要可以单独保留。

升级前先给旧版打 tag 存档，再删除旧文件。
