# 自动驾驶：自己开车，但随时把路线图摊开

平时的协作是插值：人列提纲，AI 填。自动驾驶允许外推：AI 自己想方案、做实验、判断、纠错。代价是**一切外推都要在隔离区里留痕**，人随时能看懂它在怎么开、往哪走，并且能整段撤回。

## 1. 出发前：人给出三样东西

| 项 | 内容 | 谁能改 |
|---|---|---|
| 目的地 | 目标与验收标准，引用人写的文档小节（例如"PICKING 1.5：选出统一预处理，开发集上 HR@5 ≥ P0 基线"） | 只有人 |
| 预算 | 时长、GPU 卡号、最多几轮 | 只有人 |
| 禁区 | 红线之外的额外限制（例如"不动 synth/"） | 只有人 |

人没给全的，AI 用保守默认值（6 小时、只用 CPU、最多 10 轮），写在路线图开头。

## 2. 隔离：三个区分开

| 区 | 位置 | 规则 |
|---|---|---|
| 代码 | 分支 `auto/<YYYYMMDD>-<名>`（并行时每路一个 `git worktree`） | 不碰主分支 |
| 文档 | `docs/auto/<YYYYMMDD>-<名>/` | AI 自己的文档只写在这里；人写的 `docs/` 一律只读 |
| 产物 | `runs/auto/<名>/` | 不覆盖已有产物 |

## 3. 隔离区里的三份文档

### ROUTE.md：路线图（覆盖写，永远是最新状态）

人只看这一份，就该知道现在的全貌。固定六节，每节几行：

1. **目的地**：复述目标、验收标准、预算、禁区，以及已用掉多少预算。
2. **现在怎么做**：当前路线的做法，代码在哪、产物在哪。
3. **打算怎么做**：接下来一两步做什么、预期看到什么、用什么判据判定成败。
4. **目前离目的地多远**：最新的关键数字，附出处。
5. **放弃的路线**：一行一条，写明为什么放弃、证据在 LOG 第几轮。
6. **最大的不确定**：现在最可能错在哪里。

### LOG.md：行车记录（只追加，不改旧条目）

每一轮一段：

```
## 第 N 轮（时间）
- 假设：……
- 判据（跑前写好）：结果 ≥ X 算成立，< Y 算不成立
- 做了什么：commit <hash>；命令 `…`
- 结果：数字（出处）；图 `runs/auto/<名>/…png`
- 结论：成立 / 不成立 / 说不清
- 纠正：如果推翻了之前某一轮的结论，写明是哪一轮、为什么
```

### PROPOSALS.md：交给人的提案

- 想写进人工文档的结论（附证据），人审过后由人搬进正式文档；
- 需要人拍板的选择；
- 发现的、文档里没写的东西。

### 每句话都要标明是什么

三份文档里的判断都打上标签，让人分得清哪些可以信：
- 【事实】有出处：命令输出、`文件:行号`、产物路径；
- 【推断】由事实推出，写出理由；
- 【猜测】还没验证。

## 4. 每一轮

1. 读 ROUTE.md，确认现在在哪。
2. 在 LOG.md 写下本轮的假设和判据（**跑之前写**，防止事后凑结论）。
3. 实现：先写测试；改代码；测试过了才运行。
4. 运行（只用预算内的卡和时间）。
5. 对照判据下结论，写进 LOG.md。
6. 更新 ROUTE.md；需要变道时，在第 5 节记下放弃的路线。
7. 在分支上提交：`auto(<名>): 第 N 轮 <一句话>`。

## 5. 自己纠错

- 新证据和旧结论冲突时，先在 LOG.md 写"纠正"，再改 ROUTE.md。不悄悄改写历史。
- 同一条路线连续 3 轮没有进展，就变道或回退到上一个可用的状态。
- 一个结论只有能用命令复现，才能标【事实】。
- 只用开发集调方法；验收用的数据只在判定是否到达目的地时用一次。
- 发现自己之前写的东西有错（包括代码 bug），在 LOG.md 里明说，并补一个测试，防止同类错误。

## 6. 什么时候停

不因为需要外推而停。只在以下情况停：

- 到达目的地：验收标准满足；
- 预算用完；
- 下一步需要碰红线：删除数据、看测试集、push、改主分支等；
- 下一步需要人才能提供的东西：数据、权限、资源；
- 想改目的地或验收标准：只能人改，写进 PROPOSALS.md 后停。

交互式会话里，每次变道或每 3 轮，在回复里给一段简短路况（ROUTE.md 的第 2~4 节）。无人值守时，ROUTE.md 本身就是路况。

## 7. 收车：交回给人

1. ROUTE.md 最终版：到没到目的地，现在的做法是什么。
2. PROPOSALS.md：要人审的结论和选择。
3. 证据：关键结论的命令、数字、图。
4. 代码改动摘要：`git log --oneline main..` 和关键文件的 diff。

人决定：合并哪些代码；把哪些提案搬进正式文档（由人写进提纲，或让 AI 按铁律二填进人已列好的小节）；整段丢弃也可以，因为全部在隔离区里。

## 8. 红线（自动驾驶下同样适用）

- 不修改、不覆盖原始数据和冻结的产物。
- 不看测试集调方法。
- 不改人写的文档，不改目的地和验收标准。
- 不删除文件，不 push，不打 tag，不碰主分支。
- 只用分配给自己的 GPU 和预算。
