# 论文叙事与改稿（Paper Writing）

## 1. 叙事与查重
- **先分清贡献类型**：方法创新、数据集/基准、实证分析三类贡献的证明方式完全不同。数据集/基准工作的说服力来自数据本身（标签可信、维度覆盖、难度分层、统一协议），核心论证落在数据质量与协议设计上，不只靠跑分高低。
- **查重要早且反复做**：叙事刚成形时检索一次，动笔/投稿前再检索一次。
- **审慎声明首创性**：未经检索不写“第一个”“首次”；检索后写“据我们所知”，并直接引用最接近的工作、用表格或条目说清具体差异。

## 2. 评测防泄露与对照纪律
- **排除“谁像测试集谁分高”**：使用多个互不相干的测试域；测试集按整体单元（工区、场景、对象、时间段）留出，禁止随机切分。
- **协议先于结果写定**：划分、配置、指标、随机种子、统计检验与通过判据全部写入 `docs/records/YYYY-MM-DD_eval_protocol.md` 并冻结。看结果后的改动只能以「修订（日期 + 原因）」追加，不回头改判据。
- **测试集冻结**：看过测试集样本后，禁止据此调整训练数据、增强策略或模型结构；确需针对性改进，先拆出独立开发集并写入协议修订。
- **成对对照与跨模型验证**：证明某模块有效，必须有“有它 / 没它”的严格配对配置，并在多个基线模型上验证结论方向一致；负结果如实报告，同样是结论。

## 3. 写作风格硬规矩
- **视角与密度**：按审稿人视角写，简洁、信息密；全篇保持一条连贯主线，删减无关枝节。
- **禁止项**：
  - 不用含糊或散文化的表达，不自造新词，同一点不反复强调。
  - **中文避免使用「不是……而是」句式**，直接陈述事实与对比。
  - 没有实验数据或文献依据的地方填 `【待补：具体缺什么】`，严禁编造解释或虚假引用。

## 4. 改稿交付格式
修改论文段落时，**不给笼统建议**，直接给出可原位替换的对照块：

```markdown
**改前**：<原文句子>
**改后**：<可直接替换的新句子>
**理由**：<一句话说明改了什么问题，如删冗余/补证据口径/贴合审稿人逻辑>
```
