# 数据与结果诊断（Data Inspect）

## 核心原则
1. **先用眼睛看，再看数字**：汇总指标只能排序和定位可疑样本，无法替代逐样本目检。
2. **分清数字来源**：把**配置值**（代码设定的目标参数）和**估计值**（算法从数据上测得的实测值）明确分开标注，禁止把估计值当真值。
3. **验证参照物本身**：用某份标签、基线或指标判对错前，先抽样看图确认参照物本身没有系统性偏差。

## Step 1 — 选样策略（避免只看平均或随机凑数）
抽取诊断样本时覆盖三类：
- **最差尾部（Worst-K）**：按误差、异常率或边界指标排最差的样本。
- **典型中位（Median）**：各分层/各测试域的代表性正常样本。
- **边界/极端档**：物理或参数处在极值档位的样本。

## Step 2 — 制作离线可视化检查工具
- 交互式查看器统一做成**单文件离线 HTML**（写入 `runs/diag/` 或复用 `tools/`），本地浏览器直接打开，不依赖外部 CDN 或托管链接。
- 查看器应支持：翻页/按样本 ID 跳转、缩放、切换归一化/显示增益、同时叠加预测值/标签/物理下界与关键元信息（配置值 vs. 估计值）。
- 通用查看器写成跨项目可复用形式，多格式用子命令或模式参数切换，不复制粘贴改一份。

## Step 3 — 分层诊断（一次只换一个变量）
当指标异常或目检发现系统性问题时，禁止直接拍脑袋改模型或大调参，按以下流程逐层剥离：
1. 列出可能环节（原始输入 → 预处理/重采样 → 标签规则 → 噪声/增强 → 模型前向 → 损失/解码 → 评测口径）。
2. 固定其余所有环节，每次只替换或关闭**一个**环节跑最小诊断样本（几组代表样本即可）。
3. 对比每个单变量对照的目检图与分层统计，锁定根因后再进入 `research-flywheel` 实施修复。

## Step 4 — 汇报格式
向用户汇报诊断结果时，必须按以下结构给出：
- **结论**：问题出在哪个环节、影响哪类样本。
- **证据**：离线 HTML / 图路径 + 具体样本 ID + 分层数字（注明配置值 vs. 估计值）。
- **下一步建议**：给 1~2 个可选方案、推荐项及理由。
