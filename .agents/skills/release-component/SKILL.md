# 组件定案与升版本（Release Component）

中间 commit 是过程，版本号与 annotated tag 是对外的稳定结论。**未经用户明确确认「告一段落」之前，禁止升版本或打 tag；不改变数据/结果口径的小修不升版本。**

## 前置检查
1. 确认工作区所有代码改动已通过冒烟测试与验收（目检图 + 关键统计指标）。
2. 确认待发布的组件名与新版本号（例如 `label-v7.2`、`synth-v7`、`eval-v2`）。
3. 确认是否需要对已有产物重新处理，以及重处理入口脚本是什么。

## 按顺序执行 4 步 SOP

### 1. 升级代码里的版本常量表
- 在组件对应的常量文件（如 `src/params.py` 或组件模块头）新增一行版本记录：`版本号 | 日期 | 一句话规则变化`。
- 确认产物写入逻辑会把新版本号写入文件元数据属性，且下游读取脚本能校验并拦截混用。

### 2. 定案模块文档与可选历史快照
- 原地更新 `docs/modules/<模块>.md` 的「现在的认识」「具体做法」「错误的认识与原因」「还没解决的」，确保与当前代码逐项一致。
- 更新 `docs/PROJECT.md` §8 模块索引中的当前版本与状态。
- 更新 `docs/TODO.md` 底部的「当前版本与关键路径表」。
- 若本次属于重大里程碑或协议修订，在 `docs/records/YYYY-MM-DD_<主题>.md` 写入一份冻结定案记录（写完后不再修改）。

### 3. 提交里程碑 commit
先展示 `git status` 与核心 `git diff`，经用户确认后提交：

```bash
git add <改动文件>
git commit -m "release(<组件>): bump to <版本号> — <一句话摘要>"
```

### 4. 打 annotated tag（经用户确认后执行）
tag 名称与版本号一致，说明必须包含以下 4 项：

```bash
git tag -a <版本号> -m "$(cat <<'EOF'
<版本号>: <一句话总结改了什么>

原因：见 docs/modules/<模块>.md（<对应章节>）
对已有数据的影响：<是否需要重处理 / 怎么重处理及入口命令>
定案记录：<docs/records/... 或 无>
EOF
)"
```

完成后提示用户核对 `git show <版本号> --stat`，不擅自执行 `git push --tags`。
